# Asset Compass 機能仕様

この文書では、Asset Compassの機能を現行実装・ロードマップ上の決定事項・将来候補に分けて整理します。現行仕様は主に `app.js`、`server.js`、`database.js`、`asset-goal-simulation.js`、`assets/version-history.json` と既存の `docs` を確認した内容です。

## ステータス

- **実装済み**: 現行コードで動作を確認できる機能。
- **仕様確定・未実装**: ロードマップで実施が決まっているが、現行コードでは未実装の機能。詳細設計が未決定なら、その点も記載します。
- **検討中 / 将来構想**: 実施・時期・仕様が確定していない候補。

## 1. 資産管理

**ステータス:** 実装済み

### 目的

証券口座ごとの保有銘柄、取得情報、現在価格を管理し、評価額と損益を確認します。

### 現行仕様

- 複数の証券口座と、保有資産ごとの口座区分を管理します。
- 対応する資産種別は日本株、米国株、投資信託です。ETF専用の資産種別は現行コードで確認できません。
- 保有資産の主な入力情報は銘柄名、symbol / 銘柄コード、資産種別、口座、口座区分、通貨、保有数量、取得単価です。
- 数量と取得値の精度は資産種別・通貨ごとに定め、許容精度を超えた入力は丸めずエラーにします。詳細は[data-design.md](data-design.md)を参照してください。
- iDeCo口座区分では資産種別を投資信託に固定し、整数円の取得金額を入力します。`cost` は取得金額と口数から導く未丸めの保存用派生値です。
- 資産種別やiDeCo区分の変更で数量・取得値の意味が変わる場合は両方をクリアします。通貨変更は取得値だけ、証券口座または通常口座区分のみの変更は数値を維持します。通常投資信託とiDeCo間の取得値自動換算は行いません。
- 確定した銘柄から別銘柄に変更すると、銘柄名・数量・取得値を引き継がず再入力を求めます。新規登録の初回確定前は、コード入力の修正だけで数量・取得値を消しません。
- 銘柄情報取得はフォーム状態とリクエストの一致を確認し、フォームを閉じた後などに届いた古い応答を現在の画面へ反映しません。
- 数量と取得値の入力エラー表示は独立し、該当欄の背景色で示します。
- 株式等の銘柄名・価格はYahoo Financeを利用します。投資信託はYahoo!ファイナンス日本版のページから銘柄名・基準価額・価格日付等を取得します。
- 評価額、取得額、評価損益、評価損益率は、保存された数量・取得単価・価格・為替から表示時に集計します。これらの集計値を保有資産レコードの永続化フィールドとしては持ちません。
- 価格・為替更新後のデータはSQLiteに保存され、最終取得時刻と銘柄ごとの価格日時は別々に扱います。
- 状態の正本はサーバー側SQLiteです。LocalStorageはブラウザーキャッシュおよび初回移行元として利用します。

### 主な動作

- 保有資産と口座の追加・編集ができます。
- 価格更新は登録銘柄ごとに実行されます。
- 評価額は数量と価格から計算し、投資信託は1万口単位で計算します。USD建て資産は利用可能なUSD/JPYで円換算します。
- 価格が取得できない場合は一覧上で未取得・不明として扱います。部分的な価格取得結果を全資産の値として誤表示しないよう、表示処理では値の有無を確認します。
- TOPでは口座別の評価額・損益・損益率を集計します。

### 数値精度・編集動作

現在の精度定義は `holding-number-rules.js` に集約されています。日本株は整数数量・取得単価小数2桁、米国株は小数4桁数量・USD単価小数4桁・JPY単価小数2桁、通常投資信託は整数口・取得基準価額整数円、iDeCoは整数口・取得金額整数円です。入力検証は文字列の桁数も確認し、超過値は自動丸めせず保存を拒否します。表示精度はPC・スマートフォンで共通です。

iDeCoの整数円相当判定は通常のAPI保存境界でも行い、数量または`cost`の変更時に組み合わせを再検証します。既存の規則外ペアは初回LocalStorage移行では検査・正規化せず、後続保存でも数量・`cost`ペアとその意味が変わらない間は維持できます。名称など他の項目だけを編集しても既存ペアを強制修正しません。

資産種別やiDeCo区分の変更で数量・取得値の意味が変わる場合は両方をクリアします。通貨変更は取得値だけ、証券口座または通常口座区分のみの変更は数値を維持します。確定銘柄からの銘柄変更では銘柄名・数量・取得値を引き継ぎません。新規登録の初回確定前はコードを修正してもクリアしません。非同期取得と項目別エラー状態の仕様は[data-design.md](data-design.md)および[screen-design.md](screen-design.md)を参照してください。

### 関連データ

詳細なフィールド、SQLiteテーブル、同期方式は [data-design.md](data-design.md) と [architecture.md](architecture.md) を参照してください。

### 未確定 / 要確認

- ETFを独立した資産種別として登録・分類する方針は要確認です。
- 保有資産・口座の削除操作は現行画面で確認できません。

## 3. 資産目標シミュレーション

**ステータス:** 実装済み

### 現行仕様

| 項目 | 現行仕様 |
| --- | --- |
| 入力 | 現在資産、目標資産、毎月積立額、想定年利。開始年月は実行時の現在年月を使い、期間を年・月で指定する入力欄はありません |
| 初期値 | 現在資産は画面初回表示時の総資産、目標資産100,000,000円、積立0円、年利7% |
| 実行 | 「シミュレーション」ボタンを押した時だけ計算結果を更新 |
| 月利 | `Math.pow(1 + annualReturnRate / 100, 1 / 12) - 1` |
| 月次更新 | `次月資産 = 前月資産 × (1 + 月利) + 月末積立額` |
| 上限 | 1200か月 |
| 結果 | 達成率、目標までの残額、達成予想年月、残り期間、状態別結果カード・メッセージ、資産推移グラフ、年次リターン一覧 |

計算は `AssetGoalSimulation.calculateAssetGoalSimulation()` に共通化されています。年利から複利月利を算出し、各月に運用益を反映した後で月末積立を加えます。計算期間の上限は1200か月です。UIに月利・到達月の別計算は置いていません。

結果状態は「達成済み」「達成見込み」「期間内に未達」です。達成率・残額等は計算モジュールの結果を使用します。結果カードのドーナツは100%を上限に描画しますが、中央の率は実際の達成率を表示します。入力条件は保存せず、入力を変更しただけでは結果を再計算しません。

### グラフ・年次リターン

- グラフは総資産の折れ線と薄いエリア、目標額の破線、目標到達時のマーカー・年月注記を表示します。目標額の可視テキストラベルは表示せず、目標額・到達年月はSVGの`aria-label`に保持します。
- 月の実時間に比例してデータ点を配置します。横軸は開始年の1月から始め、資産線は実際の開始年月から描画します。
- X軸ラベルの基準間隔は、PCでは期間2年未満が6か月、6年以下が1年、6年超が2年です。スマートフォンでは3年未満が1年、6年以下が2年、6年超が4年です。画面幅に応じてラベル間隔をさらに広げる場合があります。
- Y軸は目標額とシミュレーション最大額の大きい方より上に余白を置き、読みやすい1・2・5系列の刻みを選びます。目盛りは最大7本を目安にします。
- SVGの高さはPCで330px、スマートフォン幅（600px以下）で270pxです。
- 年次リターンはシミュレーションデータを再集計し、年、年初資産、年末資産、年間積立、年間運用益、年間リターン率を表示します。初年度・最終年度が部分年でも含めます。年間運用益は「年末資産−年初資産−年間積立」、リターン率は「年間運用益÷年初資産×100」です。年初資産が0の場合の率は「—」です。
- 月次データには累積積立額と累積運用益も含みますが、現行グラフでは別系列としては描画しません。年次行データには累計値も計算しますが、テーブルには表示しません。

### 関連画面・データ

画面構成は [screen-design.md](screen-design.md)、計算モジュールは `asset-goal-simulation.js` を参照してください。結果や入力値を永続保存する仕様は現行実装にありません。

### 未確定 / 要確認

- 1200か月は計算上限であり、ユーザーが変更できる期間入力欄ではありません。
- 目標額の初期値は1億円ですが、シミュレーションごとに変更可能です。入力の次回起動時への保存はありません。
- TOPの目標進捗やQuest Modeとの連携は未実装です。

## 4. 資産天気・市況天気

**ステータス:** 実装済み

### 資産天気の現行仕様

TOPの総資産評価額カードに、総資産の前日比率から判定した資産天気SVGを表示します。画面のラベルとSVG定義は状態キーを共用します。値がnull、不正値、比較不能の場合は天気アイコンを表示しません。

| 騰落率 | 内部状態 | 表示上の意味 |
| --- | --- | --- |
| +5%以上 | `special` | 特別に良い状態 |
| +3%以上、+5%未満 | `very-sunny` | 強い晴れ |
| +0.5%以上、+3%未満 | `sunny` | 晴れ |
| -0.5%以上、+0.5%未満 | `partly-cloudy` | 晴れ時々くもり |
| -3%より大きく、-0.5%未満 | `cloud` | くもり |
| -5%以上、-3%以下 | `rain` | 雨 |
| -5%未満 | `storm` | 荒天 |

境界値は `getAssetWeatherState()` の条件式に基づいています。特に-3%ちょうどは`rain`、-5%ちょうども`rain`です。

### 市況天気の現行仕様

- USはS&P500とNASDAQ100、JPは日経平均とTOPIXの騰落率を取得し、2指数の平均を市場の騰落率として扱います。
- 平均騰落率を資産天気と同じ `getAssetWeatherState()` に渡し、同じ状態アイコンを使います。
- 両指数の値がそろった場合、US・JPの平均騰落率をPCのTOPに表示し、個別指数と平均をツールチップで確認できます。
- スマートフォン幅では平均騰落率をCSSで隠し、US / JPコードと天気表示を残します。
- 指数データが不足する場合は平均値を表示せず、天気アイコン位置には「—」を表示します。

### 仕様との差・要確認

依頼時に提示された説明用ラベル（例：小雨、大雨、台風）と現行コードの`cloud` / `rain` / `storm`ラベルは完全には一致しません。現行コードでは-3%から-5%までが`rain`、-5%未満が`storm`です。境界や表示名称を変更する場合は、判定関数・アイコン・説明を合わせて更新する必要があります。

## 8. 資産推移・日次スナップショット

**ステータス:** 実装済み

### 現行仕様

- 価格更新に伴って、JST日付単位の総資産スナップショットと口座別スナップショットをSQLiteに保存します。同じJST日付の記録は更新されます。
- 総資産スナップショットは評価可能資産の合計、為替レート、保有件数、評価済み件数、未評価件数、取得失敗件数、完全性フラグなどを持ちます。
- TOPミニチャートと資産推移詳細はスナップショットの評価額を表示します。
- 表示期間は1ヶ月、3ヶ月、6ヶ月、年初来、1年、全期間です。
- 詳細画面では総資産または口座別に表示対象を選択し、前回比と期間変化も確認できます。
- 欠損値を0に置換せず、欠損地点を越えてチャート線をつなぎません。2点の有効値でも線を描画できます。

### 将来拡張

スナップショットを利用した分析強化がロードマップ上の候補です。現行画面に評価損益・配当・株価要因・為替要因の時系列分析はありません。

## 11. Quest Mode

**ステータス:** 検討中 / 将来構想

### 現行仕様

現時点では未実装です。現行の資産目標シミュレーションは通常の数値・チャート表示であり、ゲーム要素やQuest Modeとの連携はありません。

### 構想

- 1億円をラスボスとして表現し、目標資産をHPのように表示する。
- 通常モードの達成率ドーナツに対し、Quest ModeではHPゲージ等を使う。
- 現在資産、積立額、想定リターンから到達までの期間を討伐期間として表現する。
- 積立、資産増加、配当、ポイント投資、マイルストーン達成、相場下落、回復等をイベント候補とする。
- 配当月10万円を「裏ボス」とする案がある。

上記は遊び要素を含む構想で、正式仕様ではありません。通常モードと切り替える方法、イベントの発生条件、演出、データ保存は未確定です。

## 12. 為替関連

**ステータス:** 実装済み（現在レート取得・円換算） / 検討中（取得時為替・損益分解）

### 現行仕様

- 米国株・USD建て価格の円換算にUSD/JPYを使用します。
- 為替レートの取得対象はYahoo Financeの`JPY=X`です。
- TOPにUSD/JPYレートとYahoo側の為替日時を表示します。Asset Compass側の最終取得日時とは別の時刻です。
- SQLiteに現在レートと時刻を保存します。
- 為替が必要だが有効レートがない場合、USD建て資産は円評価できないものとして扱います。

取得先・timestamp・表示までの詳しい経路は[architecture.md](architecture.md)を参照してください。

### 将来構想

取得時為替の保存、株価変動と為替変動による評価損益の分解はロードマップ上の候補です。現行の損益計算では取得時為替を別に保存していません。

## 14. バージョン履歴

**ステータス:** 実装済み

### 現行仕様

- `assets/version-history.json` をPC・スマートフォン共通で読み込みます。
- JSONの各履歴には `version`、`date`、`commits` があり、コミットごとに `message` と `changes` を持ちます。
- 新しい履歴から表示します。入口に表示する現在バージョンは先頭の履歴レコードを使い、表示時に`v`を付けます。
- PCではサイドバー下部のバージョン表示から中央モーダルを開きます。
- スマートフォンでは上部ブランド近くのバージョン表示から専用画面を開きます。

### 関連画面

画面ごとの表示仕様は[screen-design.md](screen-design.md)、更新フローは[release-flow.md](release-flow.md)を参照してください。

## 個別株の自動分類サービス（v0.2.8）

分類マスタと既存のauto保存列を利用するサーバー側サービスを実装しています。米国株はdrillr、日本株はYahoo JPの業種情報を取得し、内部セクターコードへ正規化します。業種は取得元に依存するコードとして保持します。

感応度はセクターを中心に判定し、情報技術セクターの半導体業種は景気敏感へ補正します。判定できない場合は未設定のままです。API失敗・未知値・解析失敗は既存auto値を消しません。user指定値は変更せず、将来の表示でもuserがautoより優先されます。

現在は`classifyHolding`／`refreshClassification`の再利用可能なサービス関数までの実装です。価格更新や保有編集に自動実行を組み込まず、UI・投信／ETFのカテゴリ自動分類・定期更新は追加していません。
