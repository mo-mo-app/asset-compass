# Asset Compass 画面仕様（現行）

この文書は、2026-10-01 時点の `index.html`、`styles.css`、`app.js`、`asset-goal-simulation.js`、`holding-number-rules.js`、`assets/version-history.json` で確認できる画面仕様をまとめたものです。記載内容は現行実装に限り、未実装・未確定の内容は「要確認」としています。

## 画面構成とナビゲーション

アプリはページ全体を再読み込みせず、`app.js` の画面切替処理で複数のビューを表示します。

| ビュー | 主な用途 | ナビゲーション |
| --- | --- | --- |
| TOP | 資産全体の概要 | メインナビ「TOP」 |
| 保有資産 | 保有銘柄の一覧・追加・編集 | メインナビ「保有資産」 |
| 証券口座 | 口座一覧・追加・編集 | メインナビ「証券口座」 |
| 資産目標シミュレーション | 条件入力と目標到達予測 | メインナビ「目標」 |
| 資産ヒートマップ詳細 | 口座横断のヒートマップ | TOPカードから遷移 |
| 資産推移詳細 | スナップショットによる推移確認 | TOPカードから遷移 |
| バージョン履歴 | 更新履歴 | PCはモーダル、スマホは専用ビュー |

PC（幅 901px 以上）では左サイドバー、スマートフォン（幅 600px 以下）では上部ブランド表示と下部ナビを使います。601〜900px ではサイドバーを細くし、メインナビのラベルを省略する中間レイアウトです。タブレット幅で各画面をどう使うかは個別に定義されていません。

各ビューはデータを同じアプリ内状態から描画します。ヒートマップ詳細、資産推移詳細、バージョン履歴を開いた際は、ナビ上ではTOPが選択状態になります。

## 1. TOP / ダッシュボード

### 目的

総資産と損益の概要、資産種別ごとの配分、口座別集計、資産推移、ヒートマップ、保有資産の一部をまとめて確認する画面です。

### 主な表示項目

| 項目 | 表示内容・ルール |
| --- | --- |
| 価格取得情報 | 登録銘柄の取得済み件数、最終取得日時、日本円換算の案内を表示 |
| 市況 | US・JPの市況天気アイコン。2指数が揃う場合の平均騰落率はPC、スマホとも表示 |
| 総資産評価額 | 評価額を合算し、取得額も補助表示。取得可能なスナップショットがある場合は小さな推移線を表示 |
| 資産天気 | 前日比を既存の7段階判定に渡し、該当する資産天気SVGを表示。前日比が不明ならアイコンを隠す |
| 評価損益 | 評価額と取得額の差、および評価損益率を表示 |
| 前日比 | 当日価格と比較価格から得た前日比額・率を表示 |
| 資産配分 | 日本株・米国株・投資信託の評価額構成をドーナツと凡例で表示 |
| 口座別サマリー | 口座名、評価額、評価損益、評価損益率を一覧表示 |
| 資産推移 | 期間切替付きSVGチャート。初期期間は1ヶ月 |
| 資産ヒートマップ | 評価額上位8銘柄のタイルを表示 |
| 保有資産 | 共通の並び順の先頭5件を表示 |

口座別のドーナツグラフは現行TOPにありません。ドーナツは資産区分別の資産配分に使われています。

### 操作

- 「価格を更新」で価格更新処理を開始します。
- 資産推移は「1ヶ月 / 3ヶ月 / 6ヶ月 / 年初来 / 1年 / 全期間」を切り替えられます。
- 「詳細を見る >」から資産推移詳細またはヒートマップ詳細へ移動します。
- 保有資産の「詳細を見る >」は保有資産ビューを開きます。
- 口座別サマリーの「編集する >」は証券口座ビューを開きます。
- 保有資産のプレビューは5件に固定されています。

### PC版

- 901px 以上では左に固定サイドバー、右にメイン領域を配置します。
- 価格取得情報と市況表示を同じ上部行に置き、市況側を右寄せします。画面幅に余裕がない場合は行の折り返しを許容します。
- 総資産評価額・評価損益・前日比の3カードを横並びにします。総資産カードには資産天気アイコンを右上、幅に余裕がある場合はカード右側にスパークラインを配置します。
- 資産配分と口座別サマリーを2列で配置します。
- 資産推移とヒートマップを2列で配置します。
- 保有資産プレビューはその下に配置します。

### スマホ版

- 600px 以下ではサイドバーを隠し、画面上部にロゴ、下部に4項目の固定ナビを表示します。
- 総資産カードを左側に縦2段分、評価損益・前日比を右側に上下配置します。総資産カードでは金額の横に資産天気アイコンを置きます。
- 価格取得情報は途中で折り返さない1行表示にし、市況はその下の独立行に配置します。市況の平均騰落率はスマホでは表示しません。
- TOPの保有資産は銘柄名・評価損益・評価損益率のコンパクトな3列表示です。株式はsymbol、投資信託は銘柄名を使い、投資信託名は1行で省略します。
- メイン領域下部には固定ナビ分の余白を確保します。

### 表示順・文字と数値の扱い

TOPは概ね、価格・市況情報 → 3つの指標カード → 資産配分と口座別サマリー → 資産推移とヒートマップ → 保有資産の順です。

銘柄名・口座名などの日本語テキストは左寄せです。金額や率は数値列・指標カード内で右寄せまたは数値用書体で表示します。口座別サマリーの見出しは口座名を左、評価額・評価損益を右、評価損益率を列内中央に配置します。評価損益・前日比は正負に応じた色、評価損益率は共通バッジで強調します。総資産額とカードタイトルも太字・大きめの表示です。

### 関連データ

- アプリ状態の保有資産・口座データから、評価額・取得額・損益を表示時に集計します。
- 資産推移は `/api/v1/snapshots` のスナップショットを利用します。
- 市況は `/api/v1/market-weather`、為替・価格取得状態はアプリの価格取得状態を利用します。

### 要確認

- TOP上部の価格取得件数は銘柄単位ですが、複数口座で同一銘柄を持つ場合の集計表示上の重複ルールは画面仕様としては明文化されていません。
- 資産天気の数値境界は実装済みですが、将来の判定基準として固定された仕様かどうかは要確認です。

## 2. 保有資産

### 目的

登録済みの保有資産を口座・口座区分・資産種別ごとに確認し、追加・編集する画面です。独立した銘柄詳細画面は現行コードにありません。

### 主な表示項目

| 項目 | 表示内容・ルール |
| --- | --- |
| 銘柄情報 | 銘柄名。2段目にsymbol・証券口座名・資産区分を表示 |
| 価格日時 | 株式は価格取得日時、投資信託は基準日を表示できる場合に表示 |
| 現在値 | JPY建ては円、USD建てはドル表記。未取得時は「未取得」 |
| 保有数 | 日本株・米国株は株、投資信託は口数を付けて表示 |
| 評価額 | 日本円換算額。評価できない場合は「—」 |
| 評価損益 | 金額と正負に応じた色。算出できない場合は「—」 |
| 評価損益率 | 固定幅の共通バッジ。値がない場合は「—」 |
| 資産区分 | 日本株・米国株・投資信託 |
| 編集 | 行末のメニューから既存保有資産の編集ダイアログを開く |

### 操作

- 証券口座・資産区分の2つのフィルターで一覧を絞り込めます。
- 「＋ 保有資産を追加」で追加ダイアログを開きます。
- 各行の編集メニューで編集ダイアログを開きます。
- 銘柄名検索用の「銘柄情報取得」ボタンがあります。
- 一覧は証券口座の順、口座区分の順、資産種別（米国株 → 日本株 → 投資信託）、symbol昇順で表示します。口座区分名は登録済み定義を使い、未割当は「未設定」と表示します。
- 一覧行をクリックしたときの銘柄詳細遷移は実装されていません。

### PC版

- 901px 以上ではテーブル状の横並び行です。銘柄情報、現在値、保有数、評価額、評価損益、評価損益率、資産区分、編集操作を列として表示します。
- 画面幅に応じて列幅を調整し、1100px 以下では一部の任意列を省略します。
- 見出し行で列名を示します。数値項目は横並びで読み取れるように配置します。

### スマホ版

- 600px 以下ではテーブル見出しを隠し、銘柄ごとのカード状レイアウトに切り替えます。
- 銘柄情報を上段に置き、現在値・保有数・評価額を中段、評価損益・評価損益率を下段に配置します。
- 資産区分の独立表示は省略し、銘柄情報の2段目に含めます。編集メニューはカード右上です。
- フィルターは2列、追加ボタンは全幅で表示します。

### 追加・編集ダイアログ

証券口座、口座区分、資産区分、通貨、銘柄名、symbol / 投信コード、保有数量、取得単価を入力します。投信コード入力では半角英数字8文字を受け付け、英字を大文字化します。銘柄情報取得、入力検証、iDeCo選択時の取得金額・取得単価計算などはフォーム内に実装されています。入力欄や条件によって表示ラベル・補助説明が変わります。

### 要確認

- 保有資産の削除操作は一覧・行メニューで確認できません。削除機能の有無・提供場所は要確認です。
- PCの中間幅で省略する「任意列」の最終的な利用可否は、CSSのブレークポイントに依存します。

## 3. 証券口座

### 目的

証券口座の登録内容と、その口座に紐づく銘柄数・評価額を確認し、口座情報を追加・編集する画面です。

### 主な表示項目

| 項目 | 表示内容・ルール |
| --- | --- |
| 口座名 | 登録した証券口座名 |
| メモ | 任意メモ。未入力時は「メモなし」 |
| 評価額 | 口座に属する評価可能な保有資産の合計。評価可能な銘柄がない場合は「—」 |
| 保有銘柄数 | 口座に紐づく保有資産の件数 |

### 操作

- 「＋ 口座を追加」で口座名・任意メモを入力するダイアログを開きます。
- 各口座カードのメニューから編集できます。
- TOPの口座別サマリーに表示される集計はこの口座と保有資産の紐付けを元に算出します。

### PC版 / スマホ版

- PCでは口座カードを最大3列で配置します。
- 601〜900pxでは2列、600px以下では1列です。
- 口座カード内に保有資産一覧は表示されません。口座を押して口座専用詳細へ遷移する動作も確認できません。

### 要確認

- 口座削除機能は画面上で確認できません。口座削除と、紐づく保有資産の扱いは要確認です。
- 口座カテゴリは保有資産の「口座区分」と別概念です。証券口座画面自体には口座区分ごとの集計表示はありません。

## 4. 資産目標シミュレーション

### 目的

現在資産、目標資産、毎月積立額、想定年利から目標到達時期を試算する画面です。画面は `AssetGoalSimulation.calculateAssetGoalSimulation()` を利用します。

### 入力項目と初期値

| 入力 | 現行の初期値・入力ルール |
| --- | --- |
| 現在資産 | 画面に初めて入った時点の総資産を反映。金額入力は3桁区切りで表示 |
| 目標資産 | 100,000,000円 |
| 毎月の積立額 | 0円 |
| 想定年利 | 7%。3% / 5% / 7% / 10% のプリセットあり |
| 開始年月（自動） | シミュレーション実行時の現在年月。ユーザーが編集する入力欄ではありません |

### 操作と結果

- 「シミュレーション」ボタンを押した時点で入力値を読み、結果を更新します。入力欄を編集しただけでは既存結果を再計算しません。
- 結果カードは達成済み・達成見込み・期間内に未達の状態を表示します。達成率ドーナツ、状態説明、目標までの残額、達成予想年月、残り期間など、状態に応じた主要数値を示します。
- 達成率ドーナツは100%を上限として描画しますが、中央の数値は100%超を含む計算上の達成率です。
- 結果の下に状態別のサマリー文、資産推移グラフ、年ごとのリターン一覧を表示します。
- 既に目標達成済みの場合は達成済み表示、上限1200か月以内に未達の場合は到達予測なしとして扱います。
- 無効入力では結果を表示せず、入力エラーを画面内に表示します。

### PC版 / スマホ版

- PCでは入力欄4列、結果カード4列です。
- 601〜900pxでは入力欄・結果カードとも2列です。
- スマホでは入力欄1列、結果カード2列です。シミュレーションボタンは押しやすい全幅表示になります。
- PC結果カードは左に達成率ドーナツ、右に結果見出し・状態・説明・主要数値を置きます。スマートフォンは見出し・状態・説明の下に、左ドーナツ・右主要数値の2列を置きます。
- PCの結果サマリーは中央寄せ・太字・アクセント色の薄い背景を伴います。スマホでは同じ文を通常の本文として表示します。

### バリデーション

空欄や計算モジュールが受け付けない値に対して、画面内に項目別のエラーを表示します。現在資産・目標資産・積立額は金額欄のカンマを除いて数値化します。計算モジュールでは目標資産が正数であること、現在資産と積立額が0以上であること、年利が-100%より大きいことなどを検証します。

### 関連データ

- 計算処理は `asset-goal-simulation.js` の共通関数。
- 現在資産の初期値はTOPと同じアプリ内保有資産から取得します。
- 入力条件のLocalStorage保存は実装されていません。

### 資産推移グラフ

- 月次シミュレーションデータの総資産を折れ線と薄いエリアで表示し、目標額を破線、達成月をマーカーと「達成 YYYY年M月」の注記で示します。
- 目標額の可視テキストラベルはありません。目標額と達成年月はSVGの`aria-label`に含めます。各点には年月と予想資産額のアクセシブルなラベルがあります。
- X座標は月数に比例します。横軸は開始年1月から始まりますが、開始前の資産データは補完せず、折れ線は実際の開始月からです。達成点も実際の達成月に配置します。
- X軸ラベルの基準間隔は、PCでは2年未満が6か月刻み、6年以下が1年、6年超が2年刻みです。スマートフォン（600px以下）では3年未満が1年、6年以下が2年、6年超が4年刻みです。ラベル同士の最小間隔を保つため画面幅に応じて刻みを拡大する場合があります。年ラベルは1月位置、6か月刻み時の中間ラベルは7月です。
- 目標達成時は達成点の右側にも表示領域を設けます。終端年の表示規則やラベル間隔によって、余白があっても年ラベルを表示しない場合があります。
- Y軸は目標額とシミュレーション資産の最大値を基準に、その上の目盛りまで確保します。刻みは読みやすい1・2・5系列から選び、目盛り本数は最大7本を目安にします。
- SVG高さはPCで330px、スマートフォンで270pxです。

### 年ごとのリターン

グラフの下に年次テーブルを表示します。項目は年、年初資産、年末資産、年間積立、年間運用益、年間リターン率です。部分年も対象月分で集計し、初年度はシミュレーション開始時点を年初資産として扱います。通常年は前年末の時点を年初資産、年内最後のシミュレーション点を年末資産として使います。

```text
年間運用益 = 年末資産 - 年初資産 - 年間積立
年間リターン率 = 年間運用益 ÷ 年初資産 × 100
```

年初資産が0の場合、リターン率は「—」です。年間積立や金額は円表示、運用益は正負の符号を付けます。PCはテーブル、スマートフォンはテーブル部分のみ横スクロール可能で、年列は左に固定します。テーブル最小幅はPCで790px、スマートフォンで600pxです。累計積立・累計運用益は年次データに保持しますが表示しません。

### 要確認

- 初期値の総資産反映は、シミュレーション画面へ初めて入る時点のデータに依存します。複数端末間で入力条件を同期する仕様はありません。

## 5. 資産推移

### TOPミニチャート

- スナップショットの総資産評価額を使った折れ線＋薄い面表現のSVGチャートです。
- 期間は1ヶ月・3ヶ月・6ヶ月・年初来・1年・全期間から選択します。初期期間は1ヶ月です。
- 有効値が0件なら状態に応じた案内、1件なら単一点、2件以上なら点を結ぶ線として描画できます。選択期間内の点がない場合もメッセージを表示します。
- nullの値は0円として描画せず、欠損区間をまたいで線を接続しません。
- 「詳細を見る >」で資産推移詳細へ移動します。

### 資産推移詳細

| 項目 | 現行仕様 |
| --- | --- |
| 表示対象 | 総資産または証券口座単位 |
| 期間 | 1ヶ月 / 3ヶ月 / 6ヶ月 / 年初来 / 1年 / 全期間 |
| サマリー | 最新評価額、前回比額・率 |
| グラフ | スナップショット評価額のSVG折れ線・エリア表示、軸ラベル、ポイント情報 |
| 期間集計 | 選択期間、期間変化額・率 |
| 戻る | 「TOPへ戻る」ボタン |

期間や対象口座を変更すると、取得済みスナップショットを使って表示を更新します。グラフのポイントではポインター、フォーカス、タップでツールチップを表示します。

グラフの値は総資産または選択口座のスナップショット `valueJpy` を使用します。評価損益の時系列グラフは現行画面にありません。

### PC版 / スマホ版

同じ画面・期間・対象切替を使用し、CSSで高さ、余白、操作部品を調整します。スマホでは対象口座セレクターを全幅にし、グラフ・統計値を縦方向中心に配置します。

### データがない場合

スナップショット取得失敗、スナップショットなし、選択期間内に点がない、選択対象の評価額がない場合を区別したメッセージを表示します。

## 6. 資産ヒートマップ詳細

### 目的と表示

保有資産を口座横断で集約し、評価額順にタイル表示します。タイルにはsymbolまたは名称、騰落率、資産種別を表示します。評価額のある銘柄をヒートマップ化し、評価額未取得・0円の銘柄は別一覧に表示します。

TOPカードは上位8グループを表示します。詳細画面は評価額のある全グループをtreemapで表示します。画面上部に銘柄数と「口座横断で集約した評価額順の一覧です」という説明があり、「TOPへ戻る」で戻ります。

同じ資産種別・通貨・symbolの保有資産は口座をまたいで集約されます。色は騰落率段階に応じた共有ヒートマップ色定義を使います。騰落率が不明なものはunknown扱いです。

### PC版 / スマホ版

TOPのタイルはPCで4列、狭い画面では列数・タイル密度を調整します。360px以下では2列です。詳細treemapは同じ情報を画面幅に合わせて再配置し、スマホでは文字サイズや余白を縮小します。

### 空状態

保有資産なし、または評価額取得済みの銘柄なしを区別して案内します。

## 7. バージョン履歴

### データ

`assets/version-history.json` がPC・スマホ共通のデータです。各履歴にはバージョン番号、日付、コミットメッセージ、変更点配列があります。表示処理は同JSONを読み込み、新しい履歴から表示します。入口に表示する現在バージョンは履歴の先頭データから設定され、表示時に `v` を付けます。

### PC版

左サイドバー下部のバージョン番号を押すと、中央の「バージョン履歴」ダイアログが開きます。履歴リストは縦スクロールに対応し、右上の×、ダイアログ外クリック、Escapeキーで閉じます。

### スマホ版

上部ブランド表示の横に小さくバージョン番号を表示します。タップするとモーダルではなく専用ビューへ切り替わります。履歴は縦スクロールで読み、「TOPに戻る」でTOPへ戻ります。

### 要確認

履歴JSONと現在バージョン定義を同じデータから読む実装です。履歴ファイルが取得できない場合の代替バージョン番号は、現行コード上では要確認です。

## 8. 追加・編集ダイアログ、その他のUI

### 保有資産の追加・編集

同じダイアログを新規登録・編集に共用します。銘柄名、口座、口座区分、資産区分、通貨、symbol / 投信コード、数量、取得値を入力します。投信コードは半角英数字8文字で、英字は大文字化します。投資信託では取得基準価額が1万口あたりである旨を表示します。

iDeCoでは資産区分を投資信託に固定し、「取得金額（円）」を整数円で入力します。取得金額と整数口数から取得単価（1万口あたり）を自動計算して補助表示します。

数量・取得値の精度は資産種別・通貨別の共通ルールを使い、桁超過を自動丸めせずエラーにします。3桁カンマはフォーカスアウト時に表示され、保存値には含めません。数量と取得値のエラーは独立し、該当項目を背景色で示します。項目自体がクリアされたときやダイアログを開き直したときは古いエラー表示を解除します。

資産種別またはiDeCo区分を変更すると数量・取得値をクリアします（通常投資信託↔iDeCoも換算しません）。通貨変更では取得値だけをクリアし、証券口座のみ、またはiDeCoを伴わない口座区分のみの変更では数量・取得値を保ちます。

編集対象の保存銘柄、または新規登録で一度確定した銘柄から別の正規化済み銘柄へ変更した場合は、銘柄名・数量・取得値を引き継ぎません。新規登録では初回確定前のコード入力修正ではクリアしません。銘柄情報を取得せず保存する場合も最終確認し、変更検出時は一度保存を止めて再入力を求めます。フォームを閉じた後に届く銘柄取得レスポンスは現在の画面へ反映しません。

### 証券口座の追加・編集

口座名と任意メモを入力します。追加と編集でタイトル・英字ラベルを切り替え、保存またはキャンセルできます。

### バージョン履歴ダイアログ

PCのみ使用し、履歴一覧をスクロール表示します。スマホでは同じ履歴を専用ビューで表示します。

### 同期状態・エラー表示

同期通知領域には状態メッセージと、必要に応じて「この端末のデータを初回移行」「サーバーに再接続」操作が表示されます。入力エラーは各フォーム内の `role="alert"` 領域を使います。共通の確認モーダル・設定画面は現行HTMLで確認できません。

## 共通UIルール

### テキスト・数値配置

- 銘柄名、口座名、説明、見出しは基本的に左寄せです。
- 金額や率は数値を読みやすくする単位・数値用書体で表示し、表形式では右寄せを基本にします。
- バッジは固定幅・中央揃えで、損益率の正負を色でも示します。
- 狭い画面では一部文字列を1行ellipsisにし、数値列は原則折り返しません。ただし画面ごとに狭幅時の調整があります。

### 金額・単位

- 日本円金額は3桁区切りと末尾「円」を使います。損益には正負の符号を付けます。不明値は「—」です。
- 保有資産の現在値はJPYを「円」、USDを「ドル」で表示します。
- 保有数量は株式を「株」、投資信託を「口」とします。
- 率には `%` を付け、小数点以下の桁数は用途ごとの表示関数に従います。

### 色・強調

- ページ背景はオフホワイト、カードは白を基本にします。
- ブランドアクセントはミント / ティール系です。損益文字・率バッジは共有CSS変数の緑・赤・中立色を使います。
- ヒートマップは損益色とは別の段階色を使い、騰落率に応じて色の強さを変えます。
- アイコンはインラインSVGまたは既存SVG素材を使い、見出しやナビで線画のデザインルールを共有します。

### ナビゲーション・戻る操作

- PCは左サイドバー、スマホは下部固定ナビを使います。主要ナビ項目はTOP、保有資産、証券口座、目標です。
- TOP内の詳細導線は「詳細を見る >」表記です。
- 詳細系ビューは「TOPへ戻る」または「TOPに戻る」ボタンを使います。
- PCのバージョン履歴はモーダル、スマホは専用ビューです。

### レスポンシブ

- 901px以上を広いPCレイアウト、601〜900pxを中間レイアウト、600px以下をスマホレイアウトとしてCSSで切り替えます。
- PCの複数列カード・フォームは幅に応じて1〜4列へ変化します。
- スマホではサイドバーを隠し、下部ナビを固定します。テーブルはカード化するなど、画面ごとに表示構造を調整します。
- ダイアログはスマホで画面幅に合わせ、フォーム行を1列にします。

## 要確認・現行画面にないもの

- 個別銘柄の独立した詳細画面は現行コードで確認できません。銘柄情報の編集はダイアログです。
- 口座別ドーナツ、口座カードから開く口座詳細ビュー、保有資産・口座の削除操作、設定画面は現行コードで確認できません。
- 資産推移画面には評価額の時系列がありますが、評価損益の時系列チャートはありません。
- 中間幅（601〜900px）のタブレット専用操作仕様は定義されていません。
- 各画面のアクセシビリティ・キーボード操作について、ダイアログ以外を含む網羅的な仕様は要確認です。
